# CI/CD

Push hoặc pull request vào `develop`/`main` chạy ba job song song: `quality` (lint, typecheck, unit, build, audit), `operations` (release và AWS rollback fixtures), `e2e` (Playwright). Playwright cache Chromium theo `package-lock.json`; job E2E có thể rerun riêng. Push chỉ deploy khi cả ba job thành công.

Push `develop` tự deploy lên staging S3/CloudFront tại <https://dbr746toxvnoy.cloudfront.net>. Push `main` tạo deployment production ở trạng thái chờ; reviewer `TrieuNguyenPhu` phải approve trong GitHub Actions rồi job mới nhận AWS secrets và deploy lên <https://d2pqq5rtvfmo3w.cloudfront.net>. GitHub Environments chỉ cho `develop` vào staging và `main` vào production. Mỗi environment có `AWS_DEPLOYMENT_JSON` (account, region, bucket, distribution, domain, MediaFunctionName) và cặp secret AWS riêng. Job deploy chạy `ops/aws/deploy-aws.ps1`: kiểm tra account, bucket, distribution; build lại frontend và Lambda trên Linux, cập nhật Lambda và kiểm tra API trước khi chuyển index, upload assets trước index, đợi invalidation và smoke; nếu lỗi sau switch, phục hồi index S3 version trước.

AWS Organizations chặn GitHub OIDC qua SCP. Hai IAM users `rental-hub-github-staging` và `rental-hub-github-production` chỉ có quyền deploy website bucket, invalidation distribution và UpdateFunctionCode/GetFunctionConfiguration của Lambda tương ứng. Access keys nằm trong environment secrets, không ở repository hoặc Terraform state. Xoay khóa nếu có nghi ngờ lộ; khi SCP cho phép OIDC, thay access keys bằng role ngắn hạn.

Terraform staging ở `infra/aws/staging/`, state local tại máy quản trị; production Terraform ở `infra/aws/`. Không chạy Terraform apply trong GitHub Actions. Sao lưu hai state riêng và kiểm tra plan trước khi thay đổi hạ tầng. Website và data bucket bật versioning; script giữ assets cũ cho tab đang mở và rollback. Rollback script chỉ đổi lại frontend index, không xóa metadata/ảnh và không đổi Lambda code; API cần giữ tương thích với frontend cũ.

Rollback: lấy VersionId của `index.html` tốt trước đó rồi chạy `ops/aws/deploy-aws.ps1 -RollbackVersionId <ID>` với AWS credential và `AWS_DEPLOYMENT_JSON` của đúng môi trường. Kiểm tra URL sau rollback. `ops/aws/deploy-main.ps1` vẫn dùng được từ máy quản trị cho production thủ công.
